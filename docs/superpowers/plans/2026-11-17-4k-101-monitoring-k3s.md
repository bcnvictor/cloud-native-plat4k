# 4K-101 Monitoring k3s Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rendre `cnp-k3s` observable depuis le Grafana central et ses ClusterIPs Prometheus/Loki joignables depuis `cnp-control` via Tailscale.

**Architecture:** Un `Connector` de l'opérateur Tailscale déjà installé annonce le Service CIDR k3s ; l'ACL Terraform l'autorise. `kube-prometheus-stack` + `loki-stack` sont installés par Helm avec des values versionnées (ClusterIPs figées, relabel Promtail). Le Grafana central (docker-compose sur `cnp-control`) reçoit deux datasources provisionnées. Le runbook vit dans le README k3s.

**Tech Stack:** Tailscale K8s operator (`Connector`), Terraform provider `tailscale/tailscale ~> 0.17`, Helm charts `kube-prometheus-stack` 91.8.2 et `loki-stack` 2.10.3, Grafana provisioning, docker compose.

**Spec:** `docs/superpowers/specs/2026-11-17-4k-101-monitoring-k3s-design.md`

## Global Constraints

- Service CIDR k3s annoncé : `10.43.0.0/16` uniquement (pas `10.42.0.0/16`).
- Tag Tailscale du Connector : `tag:k8s` ; nom et hostname : `k3s-subnet-router`.
- ACL : ports `9090`, `3100`, `443`, `6443` vers `10.43.0.0/16`, source `tag:cnp-control` uniquement.
- Charts : `kube-prometheus-stack` **91.8.2**, `loki-stack` **2.10.3**, namespace `monitoring`, releases `kube-prometheus-stack` et `loki`.
- ClusterIPs figées : Prometheus `10.43.200.90:9090`, Loki `10.43.200.100:3100`.
- Label Loki ajouté : `cnp_io_group_id`, depuis `__meta_kubernetes_pod_label_cnp_io_group_id`, en plus des relabels par défaut.
- Datasources Grafana : `Prometheus cnp-k3s` (uid `prometheus-cnp-k3s`, url `${K3S_PROMETHEUS_URL}`), `Loki cnp-k3s` (uid `loki-cnp-k3s`, url `${K3S_LOKI_URL}`), aucune `isDefault`.
- Aucun changement de code backend / frontend / CLI ; aucune modification d'AKS ou GKE.
- Commandes Helm/kubectl k3s : lancées depuis `infra/oracle/k3s` avec `--kubeconfig cnp-k3s.yaml`.
- Commits : `feat|docs(4k-101): …` en français, **sans** trailer `Co-Authored-By`. Commentaires dans les fichiers : 2-3 lignes max.
- Le poste de dev n'a pas accès au cluster ni à `cnp-control` : les tâches 1-5 ne font que des vérifications locales ; la tâche 6 est exécutée par Lukas.

## Review Focus

- **ClusterIP Loki non figée en silence** : si `loki.service.clusterIP` n'est pas une clé du chart, Helm l'ignore sans erreur → testé en tâche 3 en lisant le Service rendu.
- **Relabel Promtail qui écrase les défauts** : les labels `namespace`/`pod`/`container` disparaîtraient et casseraient le backend → tâche 3 vérifie leur présence dans la config rendue.
- **Variables `K3S_*` absentes du `.env` de prod** : Grafana provisionnerait une URL vide → tâche 4 vérifie via `docker compose config` que les défauts s'appliquent.
- **`terraform apply` qui écrase des modifs console** : la tâche 6 impose un `plan` dont le diff se limite aux ajouts attendus.
- **ClusterIP déjà prise / route `10.43.0.0/16` déjà présente sur `cnp-control`** : la tâche 6 fait les pré-vérifications avant tout `apply`/`install`.
